## 2. SH평가/인증 모듈

> 담당: 안전컨설팅팀 (이창우 대리)
> 

### 2.1 핵심 컨셉: 입력 → 출력 → 자동 연계

**본사 서류:**

```
[입력 1]                         [출력 1]
• 고객사 업종                    • 전사 조직도
• 임직원 명단       ────────▶   • 본사 안전보건 조직도
                                • 업무분장표
                                • 경영방침, 목표, 세부계획
                                • 교육일지, 예산서
                                         │
                                         ▼ (자동 연계)
[입력 2: 자동 반영]              [출력 2]
경영방침, 목표,      ────────▶   • 성과평가 (ON/OFF)
세부계획

```

**현장 서류:**

```
[입력 3]                         [출력 3]
• 현장 명단                      • 현장 조직도
• 출력일보          ────────▶   • 현장 업무분장표

[입력 4]                         [출력 4]
• 예정공정표                     • 일일 점검표
• 주요 공종 자료                 • 수시 위험성평가표
• 착공일/준공일     ────────▶   • 비상연락망
• 현장 주소지                    • 비상사태 대응훈련 보고서
                                • 대표이사 현장점검 일지 (ON/OFF)

```

### 2.2 🔴 구체화 필요 사항

| # | 항목 | 현재 상태 | 필요한 것 | 담당 |
| --- | --- | --- | --- | --- |
| 1 | **출력 서류 템플릿** | 없음 | 현재 사용 양식 8종 | 팀장 |
| 2 | **입력 필드 정의** | 개념만 | 상세 필드 목록 | 팀장 |
| 3 | **자동 채우기 로직** | 없음 | 어떤 값이 어디로 가는지 | 팀장 |
| 4 | **평가사별 차이** | 언급만 | 이크레더블/나이스/코데이터 차이점 | 팀장 |
| 5 | **성과평가 ON/OFF 기준** | 3등급/4등급 언급 | 구체적 조건 | 팀장 |

### 2.3 단계별 진행

```
[1단계] 템플릿 분석 (1주)

[4단계] 취합/심사 대응 (1주)
```

## 4. 알림 시스템

### 4.1 알림 타이밍

| 시점 | 조건 | 알림 내용 |
| --- | --- | --- |
| 마감 3일 전 | 미제출 있음 | 업로드 요청 |
| 마감 1일 전 | 미제출 있음 | 내일 마감 안내 |
| 마감 당일 | 미제출 있음 | 당일 마감 안내 |
| 마감 후 1~5일 | 미제출 있음 | 미제출 리스트 + 매일 알림 |

### 4.2 알림 메시지 (전문적 어조)

**마감 3일 전:**

> [더베스트안전] ㅇㅇ건설 ㅇㅇ현장의 0월 자료가 00일까지 업로드되어야 월간 보고서에 차질 없이 반영됩니다. 확인하여 업로드 부탁드리겠습니다.
> 

**마감 후 (미제출 리스트 포함):**

> [더베스트안전] ㅇㅇ건설 ㅇㅇ현장의 아래 자료가 미제출 상태입니다.
> 
> - TBM 일지
> - 위험성평가 기록
> 
> 빠른 업로드 부탁드리겠습니다.
> 

### 4.3 🔴 구체화 필요 사항

| # | 항목 | 현재 상태 | 필요한 것 | 담당 |
| --- | --- | --- | --- | --- |
| 1 | **발송 방식** | 문자/카톡 언급 | 최종 결정 | 경영진 |

### 4.4 개발 방식

| 방식 | 장점 | 단점 | 비용 |
| --- | --- | --- | --- |

# Part C. 개발 계획

## 1. 기술 스택

| 구분 | 선택 | 이유 |
| --- | --- | --- |
| **프론트엔드** | React + Tailwind | 컴포넌트 재사용, 빠른 UI 개발 |
| **백엔드** | Node.js (Express) 또는 Python (FastAPI) | 빠른 개발, AI 연동 용이 |
| **데이터베이스** | PostgreSQL | 관계형 데이터, 안정성 |
| **파일 저장** | AWS S3 또는 NAS | 증빙자료 저장 |
| **차트** | Chart.js | 레이더차트, 꺾은선 |
| **문서 출력** | docx 라이브러리 + PDF 변환 | 워드/PDF 동시 지원 |
| **알림** | 카카오 알림톡 API + SMS API | 비용 효율 |

## 2. DB 설계 (핵심 테이블)

```
[고객사]
├── id, 회사명, 업종, 계약유형(스탠다드/프리미엄)
├── 담당자, 연락처, 이메일
└── 계약시작일, 계약종료일

[현장]
├── id, 고객사_id, 현장명
├── 공사금액, 공사기간, 원도급여부, 하도급발생
├── 안전보건관리책임자, 안전관리자, 관리감독자
└── 위험성평가주기

[월간점검]
├── id, 현장_id, 점검년월
├── 점검데이터 (JSON)
├── 상태 (작성중/검토중/완료)
└── 작성자, 검토자, 완료일

[점검항목]
├── id, 대분류, 소분류, 항목명
├── 점검옵션 (실시/미실시/해당없음/미도래)
└── 조건분기 (선임조건 등)

[자료업로드]
├── id, 현장_id, 항목_id, 점검년월
├── 파일경로, 업로드일
└── 상태 (제출/미제출/해당없음)

[알림이력]
├── id, 대상, 발송일, 발송방식
├── 내용, 결과
└── 관련현장_id

```

## 3. 개발 단계

### Phase 1: MVP (5~6주) — TBS컨설팅 핵심

```
[Week 1-2] 기반 구축
├── DB 설계 및 구축
├── 사용자 인증/권한
├── 고객사/현장 관리 CRUD
└── 기본 UI 프레임

[Week 3-4] 점검 기능
├── 점검 체크 화면
├── 조건 분기 로직
├── 점수 자동 계산
└── 자료 업로드

[Week 5-6] 보고서 + 알림
├── 레이더차트 생성
├── PDF/워드 출력
├── 알림 시스템 연동
└── 테스트 및 수정

→ MVP 완료: 월간 보고서 생성 가능

```

### Phase 2: 확장 (3~4주) — 공통 기능 + 건설안전

```
[Week 7-8] 공통 기능 강화
├── 대시보드 (통계, 현황)
├── 조직도 자동 생성
├── 개정 이력 관리
└── 검토/승인 워크플로우

[Week 9-10] 건설안전팀 연동
├── 법정서류 판정 이식
├── 견적 관리
├── 고객사 DB 연결
└── 홈페이지 연동

```

### Phase 3: SH평가 (3~4주)

```
[Week 11-12] SH평가 기본
├── 입력 폼 개발
├── 본사 서류 출력 (8종)
├── 출력→입력 연계
└── 성과평가 ON/OFF

[Week 13-14] SH평가 현장
├── 현장 서류 출력 (5종)
├── 평가사별 세팅
├── 취합 대시보드
└── 심사 체크리스트

```

### Phase 4: 컨설팅 추천 (1~2주)

```
[Week 15] 추천 시스템
├── 질문 폼 개발
├── 추천 로직 구현
├── 결과 페이지
└── 상세 진단 신청 폼

[Week 16] 홈페이지 연동
├── 아임웹 연동
├── 서비스 페이지 링크
└── 신청 알림 연동

```
