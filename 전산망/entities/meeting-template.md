# TBSafe 설계 회의 템플릿

---

## 회의 참석자

| 엔티티 | 역할 | 관심사 |
|--------|------|--------|
| **Praxis** | 실무 총괄 | 구현 가능성, 일정, 실행 |
| **SafetyGuard** | 안전법령 | 법적 정확성, 보수적 판정 |
| **Architect** | 시스템 설계 | 구조, 확장성, 유지보수 |
| **FlowMaster** | UX/운영 | 사용성, 직관성, 운영 편의 |

## 회의 예시: 법정서류 판정 DB 개선

### 안건 제시
```
[안건]: 법정서류 판정 로직 DB화
[배경]: 현재 하드코딩된 판정 조건을 DB로 관리하여 유연성 확보
[제안]: legal_triggers 테이블 생성하여 조건별 판정 룰 관리
```

### 엔티티별 의견

**[SafetyGuard 의견]**
```
찬성합니다. 법령 개정 시 빠른 대응이 필요합니다.

고려사항:
1. 법 조항 참조 필드 필수 (근거 명시)
2. 유효기간 필드 추가 (개정 이력 관리)
3. 우선순위 필드 (충돌 시 어떤 룰 적용할지)

주의:
- 자동 판정 실패 시 항상 "해당됨"으로 폴백
- 판정 불가 상태 표시 기능 필요
```

**[Architect 의견]**
```
구조적으로 좋은 방향입니다.

제안 스키마:
legal_triggers (
  id SERIAL PRIMARY KEY,
  document_type VARCHAR(100),    -- 서류 종류
  condition_type VARCHAR(50),    -- 조건 타입 (amount, height, floor...)
  operator VARCHAR(10),          -- 비교 연산자 (>=, <=, ==)
  threshold_value DECIMAL,       -- 기준값
  law_reference VARCHAR(200),    -- 법 조항 참조
  effective_from DATE,           -- 시행일
  effective_to DATE,             -- 종료일 (null = 현행)
  priority INT DEFAULT 0,        -- 우선순위
  is_active BOOLEAN DEFAULT true
)

복합 조건 (AND/OR) 처리:
- condition_groups 테이블 추가
- group_id로 묶어서 처리
```

**[FlowMaster 의견]**
```
관리자 화면이 필요합니다.

필요 기능:
1. 룰 목록 조회/검색
2. 룰 추가/수정/삭제 (관리자만)
3. 테스트 기능 (조건 입력 → 판정 결과 미리보기)
4. 변경 이력 조회

UX 고려:
- 조건식 입력이 어려울 수 있음
- 드롭다운 + 숫자 입력 조합으로 단순화
- 미리보기 필수
```

**[Praxis 의견]**
```
구현 계획:

Phase 1 (MVP):
- legal_triggers 테이블 생성
- 기본 CRUD API
- 기존 하드코딩 로직 마이그레이션

Phase 2:
- 관리자 UI
- 복합 조건 지원
- 테스트/미리보기 기능

Phase 3:
- 변경 이력 추적
- 버전 관리

예상 작업량: Phase 1은 빠르게 가능
```

### 결론
